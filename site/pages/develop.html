Develop a module

A module is a small TypeScript or JavaScript program with web pages for its UI. You build it against a desktop simulator, then publish signed releases from your own GitHub repo.

The module SDK (@rcs/module-sdk), the project template and the simulator will be published to npm when the platform opens to outside developers. This page shows how development will work.

Start a module

npx create-rcs-module my-module
cd my-module
npm install
npm run dev        # the simulator, with your module loaded and reloaded on save

The simulator shows the panel and the 15 keys in a browser, plus the web view, with controls to crash the module or cut the power so you can test recovery.

What a module looks like

import { defineModule } from '@rcs/module-sdk';

export default defineModule({
  async start(ctx) {
    await ctx.state.init({ count: 0 });
    await ctx.keys.setMany([{ index: 0, label: '+1' }]);
  },
  key(ctx, e) {
    if (e.index === 0 && e.action === 'down') {
      void ctx.state.patch({ count: ctx.state.value.count + 1 });
    }
  }
});
  • module.json names the module, its version, the API version, its entry file and its UI folders.
  • ctx.state holds the module's own data and is autosaved. ctx.config holds its settings.
  • ctx.keys draws the keys; key and hold receive presses.
  • ctx.ui.send talks to your UI pages, which answer with rcs.send and listen with rcs.on('message').

Rules every module follows

  • The device is the source of truth. State and saves hold only your module's settings and presets, never the device's live state (for example a router's current routes).
  • Starting, restoring and reconnecting only read. Commands go to equipment only when an operator taps something.
  • Use the system elements and theme for a consistent look; a module may set its own colour scheme.

Package and sign

npx rcs-pack keygen --out ~/my-module.key   # once; keep the private key safe
npm run pack                               # release/<id>-<version>.zip
npx rcs-pack sign                          # release/<id>-<version>.zip.sig

Packages carry no node_modules: the unit provides the SDK, and anything else must be bundled into dist/. The template's release workflow tests, packs, signs and publishes a GitHub Release when you push a tag v<version>, with your private key stored as the Actions secret RCS_SIGNING_KEY.

Get listed

Open a pull request on rcs-releases that adds your module to index.json:

{
  "id": "my-module",
  "name": "My Module",
  "description": "What it controls, in one line",
  "repo": "you/rcs-my-module",
  "publicKey": "ed25519:…"
}

Once it's merged, units list your module, offer each new signed release as an update, and this site gets a page for it. To test on a unit before then, turn on Developer mode at the panel and upload an unsigned zip from the web view.
