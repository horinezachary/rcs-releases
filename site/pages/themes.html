Themes

A theme gives a unit your own colours, logo and title, on the panel and in the web view. It's a small JSON file you can write by hand, export from the unit, or have an AI tool make from a brand or design file.

How themes work on a unit

  • Dark or Light is set in Settings › System, on the panel or in the web view.
  • A theme can have a dark version, a light version, or both. Each version has its own colours and logo. The Dark/Light setting picks which version shows. If a theme has no version for the chosen mode, that mode uses the built-in colours with the theme's title and no logo.
  • Saved themes: a unit keeps up to 10. In the web view, Settings › System › Themes lists them, with Use, Edit, Download and Delete. Load theme file… opens a file in the editor so you can check it before you save. The panel can switch between saved themes but not edit them.
  • What it changes: the icon strip, Home, Settings, the lock screen, the web view and its sign-in page. Modules follow it too, brand colour included, unless a module sets its own colours. A module's own colours apply only inside that module. The 15 keys stay dark in every theme; only the Done and lock keys use your accent.
  • A factory reset deletes saved themes and goes back to Dark.

Make one in the web view

  1. Open the web view and go to Settings › System › Themes › New theme…
  2. Give it a name and, if you like, a title.
  3. Pick Dark or Light under Version, choose a logo and set the colours. The preview updates as you type, and the editor warns you about text that would be hard to read. Then do the other version, or remove it.
  4. Save and use. Download in the theme list gives you the file to load on other units.

The file

Save it as <name>.rcs-theme.json. Shortened (the logos are long base64 strings):

{
  "format": "rcs-theme/2",
  "name": "Example AV",
  "title": "Example AV",
  "dark": {
    "colors": { "bg": "#14181B", "surface": "#1D2327", "border": "#33404A",
                "text": "#EEF2F4", "muted": "#93A1AB", "accent": "#2BB3A3" },
    "logo": "data:image/svg+xml;base64,PHN2ZyB4bWxucz0i…"
  },
  "light": {
    "colors": { "bg": "#F6F8F9", "surface": "#FFFFFF", "border": "#D2DADF",
                "text": "#152025", "muted": "#56656F", "accent": "#0E7C70", "error": "#C62F3B" },
    "logo": "data:image/svg+xml;base64,PHN2ZyB4bWxucz0i…"
  }
}
FieldWhat it is
formatAlways "rcs-theme/2".
nameWhat the theme is called in Settings. Up to 40 characters.
titleOptional, up to 40 characters. Replaces "Rack Control Surface" in the browser tab and on the sign-in page, and in the web view header when there's no logo. Both versions share it.
dark, lightThe two versions. You need at least one. Each has colors and an optional logo.
logo (top level)Optional. Used by any version that doesn't have its own logo.

Colours

Each colour is #RRGGBB (#RGB also works). Any colour you leave out comes from the built-in palette for that mode, so a version can be as small as just an accent.

The unit mixes the other shades it needs, such as the page behind cards, hover states and dialog backgrounds, from these colours.

Logos

  • A base64 data: URL of a PNG, JPEG, WebP or SVG image, up to 256 KB. In the web view editor you just pick the image file.
  • It shows in the web view header (32 px tall, up to 140 px wide), on the panel's Home screen (56 px tall, up to 260 px wide) and on its lock screen (64 px tall, up to 320 px wide). A wordmark of about 4:1 or narrower, on a transparent background, fills those spaces best; a much wider one gets shrunk. Make raster logos at least 128 px tall so they stay sharp.
  • Give each version a logo that reads on its own background: usually a white or light logo for dark, and a black or dark one for light.
  • SVG is shown as an image only, so scripts, external fonts and linked files in it don't load. Convert text to outlines, or embed what it needs.

Readable colours

The editor warns you about these, and they're worth checking in any theme:

  • text on bg, and text on surface: contrast of at least 4.5:1 (7:1 is better on a rack panel seen from a distance).
  • muted on bg: at least 3:1.
  • accent on bg: at least 3:1, so selected items stand out.
  • Keep ok, warn and error recognisably green, amber and red. Operators read them at a glance.

Older files

Files in the first format, "rcs-theme/1" (one base of "dark" or "light", plus colors and logo), still load as a theme with that one version.

Module developers

Modules don't need to do anything: the system elements and the --rcs-* CSS variables follow the theme in use. A module that sets its own theme in module.json keeps those colours inside its own screen, and can set different ones for dark and light. Every element outside the module (the strip, Home, Settings) always uses the system theme.

Instructions for AI tools

This section is written for an AI assistant asked to make a theme from a design artifact (a brand guide, style sheet, Figma export, website or mockup). Give it this page, or this section, along with the design. The JSON Schema is the exact contract.

Output

  • Produce one JSON file named <slug>.rcs-theme.json, matching rcs-theme-2.schema.json. JSON only: no comments, no trailing commas.
  • Top level: "format": "rcs-theme/2", name (the brand or client name, up to 40 characters), title (the name to show in place of the product name, often the same, up to 40 characters), and dark and/or light.
  • Include both dark and light unless the design clearly supports only one. Then include only that one, and don't invent the other.
  • Each version is { "colors": {…}, "logo": "data:…" }. Colour values are uppercase #RRGGBB. Only these keys count: bg, surface, border, text, muted, accent, ok, warn, error.

Mapping a design to the colours

  1. accent: the brand's main colour, as used for links, primary buttons and highlights. If the brand colour fails 3:1 against that version's bg, use a darker shade for light or a lighter shade for dark, keeping the hue. A design often already has these shades in its palette.
  2. bg: the page background of the design in that mode. If the design has only one mode, derive the other from the brand's neutrals: a near-black or charcoal for dark, white or an off-white for light.
  3. surface: the card or panel colour. It may equal bg if the design uses flat layouts with borders. For dark it is usually slightly lighter than bg; for light it is often white.
  4. border: the hairline or divider colour. It should be visible against both bg and surface, without being louder than the text.
  5. text: the body text colour, at least 4.5:1 (aim for 7:1) on bg and on surface.
  6. muted: the secondary or caption text colour, at least 3:1 on bg. It may equal text if the design uses one text colour.
  7. ok, warn, error: the brand's own success, warning and error colours if it defines them, adjusted to at least 3:1 on bg. Otherwise leave them out and the built-in ones are used. Never set them to the accent or to a neutral, and keep them green, amber and red.
  8. Leave a key out rather than guess when the design gives no basis for it.

Logos

  • Use the brand's wordmark or logo lockup, not an icon alone, unless that's all the brand has. Prefer SVG, then PNG with a transparent background.
  • Use the light-on-dark artwork (often white) for dark.logo and the dark-on-light artwork (often black or the brand colour) for light.logo. If there is only one, put it at the top level as logo, and only if it reads on both backgrounds.
  • Encode it as data:image/svg+xml;base64,… (or image/png, image/jpeg, image/webp), from the real image bytes. The decoded file must be 256 KB or less, and its bytes must match the stated type.
  • An SVG must be self-contained: no <script>, no external hrefs or web fonts. Convert text to paths, or use a generic font stack. Crop the viewBox tightly to the artwork. The logo is shown at most 140 to 320 px wide and 32 to 64 px tall, so an aspect ratio of about 4:1 or narrower works best.
  • If you can't produce a real logo image, leave logo out. Don't draw a substitute for a real brand's logo.

Check before you hand it over

  1. format is "rcs-theme/2", and there is at least one of dark and light.
  2. Every colour matches ^#[0-9A-F]{6}$.
  3. Contrast in each version: text/bg ≥ 4.5, text/surface ≥ 4.5, muted/bg ≥ 3, accent/bg ≥ 3. The contrast is the WCAG 2 ratio, (L1 + 0.05) / (L2 + 0.05), from relative luminance.
  4. Each logo decodes, is 256 KB or less, and reads on its version's bg.
  5. name and title are 40 characters or fewer.
  6. Tell the person which colours came straight from the design, which you adjusted for contrast (and from what), and which you left to the built-in palette.

The person loads the file in the web view at Settings › System › Themes › Load theme file…, checks the preview, and saves it. The unit rejects a file that breaks these rules and lists every problem.
